# blahsum.live: every Blahsum show, ever

**Live site:** https://truenas-scale.tail5a1866.ts.net:10000/

blahsum.live is a self-hosted fork of [Relisten](https://relisten.net), the
live-music streaming site, serving Blahsum's live show recordings from a home
TrueNAS server through Tailscale Funnel. It is AGPL-3.0, inherited from upstream.

> **Agents:** read this file, then [`docs/EDITING.md`](docs/EDITING.md), before
> changing anything. The NAS that hosts the site also stores irreplaceable
> family photos and videos. The isolation rules below are not optional.

## How the repos fit together

The project has three public GitHub repos. This repo is the hub. The other two
are cloned **as sibling folders inside it**. They are plain clones, not
submodules, and `.gitignore` excludes them from this repo.

| Folder in this repo | GitHub repo | Branch that's live | What's in it |
| --- | --- | --- | --- |
| `.` (this repo) | [`Zmatarasso/blahsum-relisten-deploy`](https://github.com/Zmatarasso/blahsum-relisten-deploy) | `main` | `docker-compose.yml`, edge nginx (`edge/nginx.conf`), Python importer (`importer/`), secret helper scripts, docs |
| `relisten-web/` | [`Zmatarasso/blahsum-relisten`](https://github.com/Zmatarasso/blahsum-relisten) (fork of RelistenNet/relisten-web) | `main` | Next.js 16 frontend: pages, player, styles |
| `RelistenApi/` | [`Zmatarasso/blahsum-relisten-api`](https://github.com/Zmatarasso/blahsum-relisten-api) (fork of RelistenNet/RelistenApi) | `main` | .NET 10 REST API over Postgres |

`./bootstrap.sh` clones or updates both forks at the right branch. In the forks,
`master` is upstream Relisten's history and `main` is blahsum.live. Never push
to RelistenNet.

## Making an update (end to end)

1. **Edit** in the right repo (frontend → `relisten-web`, API → `RelistenApi`,
   compose, nginx, importer or docs → this repo) on a feature branch.
2. **Check** your change:
   - web: `pnpm install && pnpm audit --prod && pnpm run build`
   - api: `dotnet build -c Release && dotnet list RelistenApi/RelistenApi.csproj package --vulnerable --include-transitive`
3. **Open a PR to `main`** in that repo and merge it.
4. **Deploy on the NAS.** Rebuild and restart only relisten's own services:
   ```sh
   cd /mnt/SolidStateApps/relisten/blahsum-relisten-deploy
   git pull --ff-only
   git -C relisten-web pull --ff-only        # if web changed
   git -C RelistenApi pull --ff-only         # if API changed
   sudo -n docker compose build --pull web   # or: api / both
   sudo -n docker compose up -d
   sudo -n docker compose ps && sudo -n docker compose logs --tail 50 web api edge
   ```
   Changes to docs or a README alone need no rebuild.
5. **Verify** from outside your LAN: the site loads, a show plays, and an audio
   range request returns `206`. `/api-docs` must return 404 and `POST /` must
   return 405.
6. Back up first (`pg_dump`, see `docs/EDITING.md`) before anything that
   touches the database.

**Never** restart, update or stop the NAS's other apps (File Browser, Family
Gifts, radio, Homebridge, cactpot, Tailscale, cloudflared). Never change
TrueNAS settings. Never touch Funnel ports 443 or 8443.

## Security and isolation rules (keep these)

- No service publishes a host or LAN port. The only public way in is the Funnel
  socket to `edge`.
- Every Docker network is `internal` with `inhibit_ipv4` and no IPv6, so
  containers can't reach the internet, the LAN or the NAS host (UI, SMB, SSH).
  Don't add `ports:`, non-internal networks or extra host mounts.
- `edge` serves only `/audio/` (read-only bind of the one audio folder) and
  proxies only GET and HEAD requests to `web`. The API, Swagger, Hangfire,
  Postgres and Redis are never routed publicly.
- Containers run unprivileged (`cap_drop: ALL`, `no-new-privileges`, read-only
  root filesystems, memory limits).
- Secrets live only in `db.env` and `api.env`. Rotate them with
  `./gen-secrets.sh --force && ./rotate-db-password.sh`.
- Keep dependencies patched and images pinned. Rebuild with `--pull`.

## Where shows go

Drop recordings into `\\truenas\Blahsum\shared\radioTracksStorage`, named like
`BLAHSUM live in Brooklyn NY 4-26-25 The Gutter.mp3`, then run:

```sh
sudo -n docker compose --profile tools run --rm importer import
```

The show appears at `/blahsum/YYYY/MM/DD` within about 5 minutes.
[`docs/EDITING.md`](docs/EDITING.md) has the full naming rules, how to fix dates
and titles, the database model, track markers and how to split long shows into
songs.

## For outside contributors: layout, colors, branding

All the visual code lives in [`blahsum-relisten`](https://github.com/Zmatarasso/blahsum-relisten)
(the `relisten-web/` folder here):

| What | Where |
| --- | --- |
| Theme colors and fonts (Tailwind v4 `@theme`) | `src/styles/globals.css` (`--color-relisten-*`, `--color-foreground`, `--color-background`) |
| Page shell, title, metadata | `src/app/layout.tsx` |
| Header and navigation | `src/components/NavBar.tsx`, `MainNavHeader.tsx`, `SecondaryNavHeader.tsx` |
| Player bar | `src/components/Player.tsx` |
| Show and track lists | `src/components/*Column.tsx`, `Row.tsx` |
| About page | `src/app/(content)/about/page.tsx` |
| Icons and images | `public/` |
| Share images | `src/app/api/og/route.tsx`, `src/app/album-art/route.tsx` |

Components use Tailwind utility classes.

**Run it locally:**

```sh
git clone https://github.com/Zmatarasso/blahsum-relisten.git && cd blahsum-relisten
git checkout main
pnpm install
pnpm start          # http://localhost:3000
```

If `RELISTEN_API_URL` isn't set, the app uses upstream Relisten's public API.
That's fine for layout and color work, but you'll see Relisten's catalog rather
than Blahsum's. For the real data, run the whole stack from this repo:
`./bootstrap.sh`, then `cp .env.example .env` and set `AUDIO_DIR` to a folder of
test mp3s, then `./gen-secrets.sh`, then `docker compose up -d --build`, then
the importer. Locally you can add `ports: ["127.0.0.1:3000:3000"]` to `web` in a
`docker-compose.local.yml`. Never commit that file.

**Contributing:** fork, branch, open a PR to `main` on `Zmatarasso/blahsum-relisten`
with screenshots (desktop and mobile). Keep `pnpm run build` and
`pnpm audit --prod` clean.
